# Miku AI创作平台 · MIKU AI STUDIO

[![CI](https://github.com/misfeng-82/Miku-AI-Studio/actions/workflows/ci.yml/badge.svg)](https://github.com/misfeng-82/Miku-AI-Studio/actions/workflows/ci.yml)

浅色暖纸工作台，**22 个功能入口**，跑在一个网页里。主工程除一个官方云服务 SDK（`@tencent-ai/workbuddy-cloud-sdk`，零三方依赖）外，全是 Node 标准库 + 原生 ES Module，`npm ci` 即可跑；**无限画布是独立子服务**（`canvas/`，Express + dotenv），首次要进目录单独 `npm install`。

## 运行前提：必须接入模型

**本项目以真实模型为前提。** 剧本生成、模型评审、逐集精修这三处必须调用模型——不接就是不做，没有"兜底样本稿"这种中间态。

| 功能 | 未接入模型 | 已接入模型 |
| --- | --- | --- |
| 剧本生成 / 模型评审 / 逐集精修 | ❌ 明确报错并引导去配置 | ✅ 真实产出 |
| 24 道质量门 / 分镜切段 / 台词本 / 统计报表 / 格式转换 | ✅ **照常可用**（本地确定性代码，与模型无关） | 同左 |
| **访客自带 Key（BYOK）** | ❌ 明确提示「填你自己的 Key」，不会替发布者花额度 | ✅ 用自己的 Key 生成，Key 只存在自己浏览器里 |

**配置方式**：右上角「接 API」→ 填 Base URL / 模型名 / Key（任何 OpenAI 兼容网关均可，如 DeepSeek、通义、Ollama 本地）。
**公共站点上必须填自己的 Key**（BYOK）：Key 存在你自己的浏览器里，随请求带过去，用完即弃。
不填就没有生成能力——这是刻意的：**谁用谁填，谁填谁花钱**，不会有人偷偷花发布者的额度。

> **为什么去掉默认 mock**：样本稿能跑通链路，但内容是内置模板，会让人误判"模型写出来了"。真实项目的诚实做法是——要么真调模型，要么明确告诉你没配。
>
> 自测与离线开发仍可显式开启：`USE_MOCK=1 node src/server.js`（仅测试用途，产品路径不依赖它）。

## 无限画布（独立子服务）

画布不是一个前端页面，而是**独立的 Express 子服务**（`canvas/`，默认端口 `5180`，可用 `CANVAS_PORT` 覆盖）：

- 主服务启动时 `spawn` 拉起它；进程异常退出会在 2 秒后自动重启（`src/app.js` 的 `ensureCanvasService`）
- 主服务把 `/canvas` 与 `/canvas/*` 手写代理到子服务：**保留查询串**（任务查询、下载都依赖 query），并**移除 `X-Frame-Options`**——不移除画布在 iframe 里就显示不出来
- 对外只有一个端口 8787、一个源，不存在跨域；`canvas/node_modules` 没装时页面显示「画布服务未启动」，主工程其它工具照常可用

**生成能力需要两把令牌，不能混用**：

| 类型 | 通道 | 令牌分组 | 节奏 |
| --- | --- | --- | --- |
| 视频 | AutoDL Art · ComfyUI 工作流 | **ComfyUI** | 提交 → 轮询，15 秒镜头约 2–3 分钟 |
| 图片 | `/api/v1/images/generations`（OpenAI 兼容） | **LLM** | 同步，一次请求出图 |

令牌要么在画布页面「接入模型」里直接填，要么复制 `canvas/.env.example` 为 `canvas/.env`，填 `AUTODL_TOKEN`（ComfyUI 分组）与 `AUTODL_LLM_TOKEN`（LLM 分组）。右上角状态点会直接告诉你：绿「模型已接入」/ 黄「令牌缺 ComfyUI 权限」/ 黄「未配置令牌」。

**边界**：
- 画布数据存在浏览器 `localStorage`，换设备看不到（要多人共用得补后端存储）
- 生成结果是 AutoDL 的临时链接，**24 小时失效**，要留的片子尽快下载转存
- 按秒计费，15 秒 480p 约 0.6 元；`FORCE_MOCK=1` 可全程走模拟、不产生费用

画布自己的文档（接口、工作流 ID、提示词审核的坑）见 [canvas/README.md](canvas/README.md)。


## 云服务接入（已开通）

已接入 WorkBuddy 云服务（应用：Miku短剧创作台）。平台侧**支持免密钥调用**，但默认**只对发布者本人开放**：
匿名访客不会借用发布者的额度，必须自带 Key（见「接模型」）。

- 配置在 `src/cloud/defaultConfig.json`（公开配置：endpoint + publishableKey，仅标识应用、不带权限）；
  本机可用 `data/cloud.json` 覆盖（该文件 gitignore，不会上传）
- 调用走官方 SDK `@tencent-ai/workbuddy-cloud-sdk`（零第三方依赖），只支持流式，代码里按 chunk 收全文
- 模型默认 `glm-5.3-flash`：实测 `auto` 对长输出会卡到空内容超时，具体模型 1.5–2 秒返回
- **默认不允许匿名访客借用发布者的云额度**（`allowCloudLlm: false`）：访客不填 Key 就明确报错并提示去填，
  不会有人偷偷花你的额度；要开放给公众用，需在配置里显式 `allowCloudLlm: true`
- 来源优先级：访客请求头自带的 Key > 服务器运行时配置 > 云服务（默认关）> `.env` > 本地样本；`USE_MOCK=1` 时走样本

```bash
# 本地验证云端链路（空数据目录模拟「没填 Key」）
PORT=8901 DATA_DIR=/tmp/mk-cloud node src/server.js
curl -s localhost:8901/api/meta        # llm.mode 应为 cloud
```

### 作品已接云数据库（重新发布不丢）

作品与小说现在**存在云数据库里**（表 `kv_store`），本地 JSON 只是缓存：

- 写：先落本地（同步、不会失败），再异步 upsert 到云端（同键 400ms 合并，失败只记日志）
- 启动：端口先开 → 轻量数据（小说/索引/榜单，约 90 KB）后台拉完 → 重量数据（`project-*`，实测 18.6 MB）
  分页流式落地。列表接口最多等 3 秒，等不到就先返回当前数据
- `settings` / `cloud` 这类含密钥的键**永不同步**
- `USE_MOCK=1` 时整体关闭同步，测试数据不会污染生产库

> 第一次部署踩的坑：回灌放在 `listen()` 之前，平台 60 秒探不到端口直接判启动失败。
> 现在顺序反过来了——先开端口，再补数据。

登录 / 文件存储两个模块**尚未接入**。

## 部署（对外发布时必读）

本机跑不需要任何环境变量。**一旦对外发布，必须设 `NODE_ENV=production`**，否则：

| 后果 | 说明 |
| --- | --- |
| 静态资源不缓存 | `Cache-Control` 会是 `no-store` 而不是 `no-cache`，每次访问都全量重下 `app.js` / `views/*.js` |
| 堆栈进日志 | 仅进日志、**不返回给客户端**（`errorHandler` 已做隔离，这点是安全的） |

> 为什么默认不是 production：本地用 `PORT=8899` 调试时**恰恰需要** `no-store`，
> 否则会踩回「内置浏览器拿旧 `app.js`、代码改了页面还是旧的」那个坑。
> 所以默认值保持 development，改为**启动时检测**：只要绑定到 `0.0.0.0`
> 且 `NODE_ENV` 不是 production，就打印 `server.env.exposed` 告警。看到这条就说明忘了设。

```bash
NODE_ENV=production PORT=8080 node src/server.js
```

### 公开部署与 Key 的冲突

以前的版本把 Key 存在服务器上，一旦部署到公网就是「所有访问者共用同一个 Key」。现在改成 **BYOK**：
Key 存在每个访客自己的浏览器里，服务器不保存任何人的 Key，所以不存在「共用一把 Key」的问题。

注意剩下的一点：**作品数据仍然是共享的**（同一个站点一份 `data/`），要隔离得做账号体系（未做）。

1. **用 BYOK（推荐，本项目云端站点就是这么跑的）**：Key 存在每个访客自己的浏览器里，服务器不需要放任何 Key；
   访客不填就明确拒绝，谁都不会花你的额度
2. **不公开部署**：自己本机跑、或团队内部网络跑——这是最符合「谁用谁自己搭」的用法
3. **要公开又用自建 Key**：设 `ACCESS_TOKEN`（访问口令）+ `LLM_DAILY_TOKEN_LIMIT`（日额度上限），把共用 Key 的滥用风险压到最低——但仍无法做到「每个用户独立 Key」


## 接模型

**Key 存在你自己的浏览器里**（localStorage），随请求头 `x-llm-*` 发给服务，用完即弃：
不落盘、不写日志、不上传别处。公开站点上每个人的 Key 互不可见，也不会有人替你花额度。

> 以前的版本把 Key 存服务器 `data/settings.json`——公共部署时这等于「所有访客共用一把 Key」。
> 现在改成了 BYOK（bring your own key）：**谁用谁填，谁填谁花钱**。

顶栏「接 API」里填。解析优先级：**访客请求头自带的 Key > 服务器运行时配置 > 云服务（默认关）> `.env` > 本地样本**。

- 预设里已带 **DeepSeek V4.1 Flash**（`deepseek-flash` · 1M 上下文 · 支持图像）和 **DeepSeek V4 Pro**（`deepseek-v4-pro`）；老的 `deepseek-chat` 已被官方下线，打开弹窗会自动纠正过去
- **推理等级**：`不指定`（服务端默认，DeepSeek 为 High）/ `Low` / `High` / `Max` / `关闭思考`。只有选了具体档位才会发 `reasoning_effort` + `thinking`，不认识这两个字段的网关请保持「不指定」
- 思考模式下温度不生效；思维链与正文共用「最大 Token」，长剧本要留够余量
- 改完点「测试连接」验证，通了再勾「启用」

  > 服务器端的 `data/settings.json` 只在「你自己本机用」或「.env 注入」时才有意义；
  > 公共站点上访客的 Key 在浏览器里，不经过服务器磁盘。
  
  ### Key 的生命周期（谁用谁搭，离开可抹除）
  
  本项目是**单机工具**，不是 SaaS。Key 的设计遵循「谁用谁自己搭」：
  
  | 阶段 | 行为 | 说明 |
  | --- | --- | --- |
  | **保存** | 写入**你自己浏览器**的 localStorage | 不上传服务器、不进 git；别人打开同一站点看不到你的 Key |
  | **使用** | 随请求头 `x-llm-*` 发给服务，仅本次请求内使用 | 不落盘、不写日志、不回显；用完即弃 |
  | **抹除** | 弹窗底部「抹除配置」按钮 | 清掉浏览器里的 Key 与 Base URL，**不可恢复** |
  
  **抹除的时机由你决定**——换人使用、换电脑、不再用了，点一下就干净。不会自动清除（关浏览器/关服务都不会丢，避免日常使用被打断）。
  
  ⚠️ **不要再用「把 Key 写进服务器」的办法做公共部署**：那等于所有访客共用你的 Key。
  公共站点请走 BYOK——每个访客填自己的。见下方「部署」一节。

## 关键决定
1. **结构性归代码，创造性归模型。** 时长折算、ID 纪律、受控词表由引擎计算；mock 模式下剧本走内置样本，接入 API 后改走模型。
2. **评估两层。** 24 道门是确定性结论（可复现、可回归），大模型评审负责门算不出来的「好不好看」，按 6:4 加权；模型失手时退回纯门分并说明原因。
3. **优化两刀。** 机器能改且一定对的先改（拆长句 / 补动作），再逐集交给模型精修；改完过门，不过就丢弃改写、保留原稿。
4. **画风是全局约束。** 12 种预设，中文/英文/反向三件套成对维护，注入所有提示词。
5. **前端按域分模块。** `public/views/{intel,script,quality,assets,tools,system,novel,canvas}.js` 按视图域拆文件 + `core.js` 状态层 + `app.js` 注册表分发，加功能只加一个文件。画布这一层只留一个同源 iframe 壳（`canvas.js`），真正的画布在子服务里。
6. **工具之间零耦合（2026-10-23 重构）。** 每个工具用自己的输入槽 `state.data.inputs[state.view]`，`ctx()` 只读当前工具那一格。没有全局"当前剧本"，没有跨工具写回，也没有"先做 A 才能做 B"的门禁——**载体是文件**：要复用剧本，导出再载入，不靠隐式共享。
7. **公网部署靠单口令，不做账号体系（2026-10-27）。** 本应用原本零鉴权，任何拿到链接的人都能删数据。加了一层可选的单口令门禁（`ACCESS_TOKEN`，留空即关闭，不影响本地与测试）：HMAC 签 cookie、`timingSafeEqual` 比口令、登录端点独立限流。另加按 IP 的全局限流与生产 HSTS。**取舍**：口令是共享凭证，所有使用者同一份数据、互相能删；要真多用户得另做账号体系。
8. **画布是子服务，不是前端模块（2026-11-12）。** 画布要放 textarea、下拉、视频，位图方案做不了；但它又是重前端，塞进主工程会把零依赖的边界打破。所以拆成独立进程独立端口，主服务只做 `/canvas/*` 代理。**取舍**：多一套依赖（Express + dotenv）和一次单独 `npm install`，换来画布可以单独跑、单独重启，崩了也不拖垮主服务（`ensureCanvasService` 还会自动拉起）。

## 部署

公网部署（Render）的完整步骤见 **[DEPLOY.md](DEPLOY.md)**。要点：
- 零依赖，构建命令可留空，启动入口 `node src/server.js`
- 必须在控制台设 `ACCESS_TOKEN`，否则等于公开裸奔
- 免费实例文件系统是临时的，`data/` 会随重启清空

## 验证

```bash
node scripts/selftest.mjs   # 135 项单元/集成自测（不需要服务；自动强制离线，不碰真 Key）
node scripts/secretscan.mjs # 提交前必跑：确认仓库里没有明文密钥（退出码可直接卡口）
node scripts/uicheck.mjs    # 前端接线审计：DOM id / 图标 / api 方法 / 页面 / 按钮处理器（不需要服务）
node scripts/enginecheck.mjs      # 引擎冒烟：夹具过 14 道大纲门 + 10 道剧本门，验 seed/stats/renderHtml
node scripts/smoke.mjs      # 59 项端到端冒烟（需服务在跑）
node scripts/featuretest.mjs      # 141 项全功能矩阵：端点 × 正常流程 + 边界情况（需服务在跑）
node scripts/rendercheck.mjs      # 45 项页面渲染：20 个视图 × 空状态/有数据 + 写作台右栏页签（需服务在跑）
node scripts/probe-import.mjs     # 剧本导入探针：两种文本格式 / JSON → 引擎契约
node scripts/probe-scriptgen.mjs  # 剧本生成探针：三段式 mock 全链路 + 门禁对账
node scripts/diag-gate.mjs        # 门禁诊断：从 data/ 捞最近一份生成稿，把未过的门连细节打出来
```

> **五套检查的分工**（只看其中一个绿灯会漏）：
> - `selftest` 管**纯函数与引擎**，不需要服务；
> - `uicheck` 管**前端接线**——「点了没反应」「页面报 undefined」这类问题只有它能静态抓到；
> - `smoke` 管**端到端主链路**能不能跑通；
> - `featuretest` 管**每个端点 + 边界**，抓「正常输入对、异常输入 500」；
> - `rendercheck` 管**每个页面能不能画出来**——在 Node 里真实执行 18 个视图函数。
>
> 全绿才算这次改动站得住。


> `enginecheck.mjs` 和 `diag-gate.mjs` 原先不在这个清单里，于是长期没人跑、
> 路径写坏了也没人发现。现在两者都由 `selftest` 覆盖（见「验证」末尾说明）。

> 冒烟里凡是要生成内容的接口都会走「当前生效的模型配置」：配了 Key 就走真模型，
> Key 无效会直接报 502（这正是设计行为——不静默降级成假数据）。想跑纯本地冒烟，
> 用一个不带头配置的数据目录启动服务即可，例如
> `DATA_DIR=data-clean PORT=8799 node src/server.js`，再对该端口跑 `PORT=8799 node scripts/smoke.mjs`。

> **冒烟可以在同一个 `DATA_DIR` 上重复跑。** 冒烟会真的建项目，而 mock 引擎固定产出
> 剧名《都市重生逆袭》，本来第二遍会被剧本生成的**剧名去重**守卫拦下
> （`502 连着两稿都和已有作品撞了`）。现在 `smoke.mjs` 开头会按名字精确匹配
> （`冒烟项目` / `生成稿冒烟`）把上一轮的残留从索引里摘掉，所以可以连续跑。
> 清洁机制是软删除——只摘索引、正文文件保留，不会动你其它项目。
