## 1. 我们现在的家底与缺口

### 已有（强项，别动）

- **爆款情报**：真实剧目榜（10 条红果官方数据，含播放页/海报/集数）、爆款拆解、对标分析
- **剧本**：三段式生成（梗概人设 → 分集大纲 → 逐集正文）、导入、格式转换
- **分镜**：15 秒段 + 3-6 子镜头、12 道结构门、摄制单提示词、自动识别登场角色
- **质量**：24 道确定性门 + LLM 评审 6:4 加权、逐集优化、统计报表
- **资产**：角色一致性提示词、场景、台词本、人物关系
- **工程**：零依赖、82 项 selftest、50+ 项 smoke、mock 优先、结构化日志

### 缺口（按价值排序）

1. **没有合规审核** —— 剧本写完到上线之间缺一整层。国内短剧过审是硬门槛。
2. **没有跨集一致性** —— 现在一个项目内的阶段各自为政；第 20 集人设崩、伏笔丢、关系乱，没有东西能查出来。
3. **分镜缺影视理论** —— 拆得出来，但景别选择、轴线是否跳、布光逻辑、转场功能，没有知识库支撑，全靠模型自由发挥。
4. **大纲缺商业化设计** —— 付费卡点、爽感配比、四层反派递进，这些是短剧的钱袋子，我们完全没有。
5. **没有溯源机制** —— 上游改了人设/场景，下游分镜与提示词不会知道，用户拿到的是自相矛盾的一套产物。
6. **没有海外格式** —— 格式转换只有国内四种，出海（ReelShort / DramaBox 那套）是空白。
7. **没有小说/IP 入口** —— 输入只能是「一句话创意」或粘贴剧本，从网文改编这条最主流的路径没有工具。
8. **没有声音资产管理** —— 只有「音色提示词」文本，没有音色来源/授权/母版的概念。

## 2. 逐项复刻方案

### 2.1 合规审核（抄 `0xsline/short-drama`）

**它有什么**：`references/compliance-checklist.md`，295 行，四类检查：

| 维度    | 检查内容                  |
| ----- | --------------------- |
| 红线检测  | 政治敏感、违法犯罪美化、色情暴力、歧视侮辱 |
| 高风险内容 | 未成年人相关、宗教民族、历史事件、医疗法律 |
| 正能量校验 | 价值观导向、社会影响、教育意义       |
| 广告植入  | 软广合规性、品牌露出方式          |

产出 `compliance-report.md`，问题分⛔阻断 / ⚠️建议 / ℹ️微调三级。

**怎么复刻**：

- 新增 `src/assets/complianceRules.js` —— 红线词表 + 高风险模式（正则）+ 正能量校验规则 + 分级权重，纯数据，和 `hotDramas.js` 一个性质。
- 新增 `src/services/complianceService.js` —— `checkScript(script)` / `checkOutline(outline)` / `checkText(text)`，逐集扫、按位置给出「第几集第几场」，和现有 `evaluateService` 的门报告一个形状。
- 挂到两处：① 剧本评估页加一个「合规」分区（红⛔直接标红）；② 项目 stage 加 `compliance`，写回和 evaluate/checkup 并列。
- 前端在质量域加一个入口，或直接并入「剧本评估」页底部 —— **建议并入，不新增侧栏项**（侧栏已经 7 组 19 项，别再涨）。
- selftest 加：红线词必须命中、正常剧本不误报、分级正确、位置定位准确。

**工作量**：1-2 天。**风险**：词表要持续维护，第一版宁可漏报不要误报（误报会逼用户反复改稿）。

### 2.2 长线连载一致性（抄 `mengxiujie/ManjuForge`，MIT-0）

**它有什么**：七个结构化记忆文件 + 三套引擎 + 三个确定性脚本，实测 6 集 Demo + 5 集真实项目「零崩坏、伏笔回收率 100%」。

| 记忆文件  | 防什么                      | 更新时机    |
| ----- | ------------------------ | ------- |
| 角色档案  | 人设崩坏（身份不变量锁死，状态变量逐集更新）   | 每集      |
| 世界观   | 设定漂移                     | 首次 + 扩展 |
| 场景布局  | 空间跳位（含光照状态字段，防跨时段崩）      | 变更时     |
| 剧情摘要  | 剧情断层                     | 每集      |
| 伏笔表   | 伏笔丢失（埋设→发酵→推进→回收）        | 每集      |
| 故事圣经  | 记不住设定（四段式总纲，每 5 集刷新）     | 每 5 集   |
| 角色关系图 | 记不住关系（矩阵 + 事件时间线 + 信任曲线） | 关系变化时   |

**22 项跨文件一致性检查**分五组：M6（记忆文件层）/ F5（伏笔表健康）/ R4（关系图）/ D3（人物状态）/ P4（分集层）。实测当场抓出三类人工漏掉的事故：场景布局文件缺失、关系图记了某人有戏但剧情摘要人物快照里没有他、七处碎片时间轴空档 2-8 秒（成片黑场）。

**怎么复刻**（这是最大的一块，建议分两步）：

**第一步：记忆文件层（2-3 天）**

- 新增 `src/services/continuityService.js`，七个记忆文件的模板 + 读写，挂在 `projectRepo` 的 stage 上（新 stage `continuity`）。
- 我们的剧本结构已经比它的 Markdown 严格（有 episodes/scenes/flow 契约），所以记忆文件直接存结构化 JSON，比它的 Markdown 更好查。
- 前端在项目模式下加一个「连续性」页（或并入统计报表），显示七个记忆文件的健康度。

**第二步：一致性检查器（3-4 天）**

- 把 22 项检查用 Node 重写（它的是 Python，我们是纯逻辑移植，不是抄代码）。
- **每条报错必须同时给出「哪两个文件矛盾」和「怎么修」** —— 这是它做得最好的地方，原样学。
- 挂到逐集生成流程里：写第 N 集前先跑检查，🔴 项拦截，⓴ 项放行。这和我们现有的「不过门就带诊断重修」是同一个模式，用户零学习成本。

**工作量**：5-7 天。**风险**：22 项检查要逐项对着我们的数据结构重新设计，不能照搬组名。第一版建议先做 M6 + F5 + D3 三组（10 项），跑两周再补 R4 + P4。

### 2.5 制品哈希 + 依赖失效传播（抄 `suihe1/short-drama-production`，Apache-2.0）

**它解决的真问题**（原文）：*「上游改了人物或场景，下游仍在使用旧素材」*。做法是记录制品哈希和依赖关系，自动传播 `stale` 状态并要求重新审批。

**怎么复刻** —— 这是**性价比最高的一项**，纯逻辑、不依赖任何外部工具：

- `projectRepo` 的 stage 写回时，除了产物再存一个 `{ hash, deps: [...] }`。
- 依赖声明很简单：`storyboard` 依赖 `script` + `cast`；`assets` 依赖 `script`；`compare` 依赖 `hot`。
- 上游 stage 被重写 → 下游 stage 的 `hash` 对不上 → 标 `stale`。
- 前端在项目下拉/首页显示「⚠ 分镜已过期（剧本在 14:32 被改过）」，一键重跑。
- 它还有个好设计：**付费提交、批量、重试都需要用户当次确认** —— 我们的模型调用同样适用，可以在 `busyBtn` 上批量跑时加一道确认。

**工作量**：1-2 天。**风险**：几乎没有。这是纯增益。

### 2.6 海外出海双格式（抄 `0xsline/short-drama`）

**它有什么**：domestic / overseas 双模式，格式对照：

| 元素  | 国内              | 海外                                   |
| --- | --------------- | ------------------------------------ |
| 场景头 | `## 场景一：客厅·内·日` | `## Scene 1: INT. LIVING ROOM - DAY` |
| 镜头  | `△ 全景：`         | `WIDE SHOT:`                         |
| 配乐  | `♪ 轻快的钢琴`       | `♪ Upbeat piano melody`              |
| 对白  | `**苏念**：（微笑）你好` | `**SU NIAN**: (smiling) Hello`       |

外加文化适配：角色名转拼音/英文、场景描述适配西方认知、剧情节奏适配海外习惯、法律/文化敏感内容自动调整。

**怎么复刻**：

- 格式转换加第 5 个目标 `hollywood-overseas`（我们已经有 `hollywood`，把它分成「国内好莱坞格式」和「海外版」两条）。
- 新增一个「海外适配」检查：人名是否英文化、是否有需要解释的中国特有概念、单位/货币/节日、法律敏感点。
- **不建议**做自动翻译（那是模型活，且我们的定位是创作工具不是翻译工具）；只做格式 + 适配检查，翻译留给用户在生成时选语言。

**工作量**：1-2 天。

### 2.7 IP 初筛评估（抄 `VanGong1999/screen-creative-skills`）

**它有什么**：31 个 skill，最值得抄的是「小说 → 短剧」这条评估链：

```
novel-summarizer → drama-evaluator → drama-planner → drama-creator → script-evaluator
```

其中 `drama-evaluator` 评三个维度：**短剧适配度 / 爽点密度 / 改编难度**；`ip-evaluator` 挖网络信息 + 传播热度 + 综合价值打分；`score-analyzer` 做批量排名（50 部小说并行 → TOP 3，约 15 分钟，人工要 1-2 天）。

**怎么复刻**：

- 新增 `src/services/ipEvalService.js`：输入一段小说文本 → 五维分析（题材/人物/关系/情节/创意）→ 改编潜力评分 → 改编建议（哪些线保留、哪些砍、预计多少集）。
- 前端新视图「IP 评估」，放在**爆款情报域**（和榜单/拆解/对标并列，都是「看别人的东西」）。
- ⚠️ **许可证要确认**：该仓库有 LICENSE 文件但网页上看不到类型，复刻前必须先 `git clone` 看 LICENSE 原文。若是非商用许可，只借鉴维度设计，不搬文字。

**工作量**：3-4 天。

---

### 2.8 声音资产卡（抄 `suihe1/short-drama-production`）

**它解决的真问题**（原文）：*「音色来源、授权范围和最终母版混在一起」*。做法是把**发现 → 试听 → 授权克隆 → 母版登记 → 使用范围**五步分开，声音资产与角色/台词/视频任务解耦。

**怎么复刻**：

- 我们 `assetService` 已有角色卡；加一种 `voice` 资产类型：`{ voiceId, source, licenseScope, evaluationOnly, masterRef, boundCharacters: [] }`。
- 台词本导出时，把每个角色的音色资产 ID 一起带出去。
- 前端资产库加一个「声音」分区。**不做实际 TTS 调用**（那是付费外部服务，违背 mock 优先），只做资产登记与约束。

**工作量**：1-2 天。

## 5. 复刻前的三个必须

1. **先 clone 看 LICENSE 原文**再动手。标「待确认」的一个都不能在确认前搬文字，只能借鉴维度设计。
2. **搬「规则与结构」，不搬「文字与影像」**。DirectorSkills 明确说了自己不含原书内容，我们同理——词表、维度、检查项、组织结构可以学，成段的描写、案例帧、书籍原文不碰。
3. **每项复刻都必须配 selftest**。这是我们项目唯一的质量底线，复刻进来的东西没有测试就等于没复刻。
