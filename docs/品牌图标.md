## 二、几何规格（唯一事实来源）

同一个 32 单位网格，所有尺寸按比例缩放，不重画。

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 画布 | `0 0 32 32` | 方形网格 |
| 圆角 | `rx="7"` | 占边长 22%，比 iOS 图标（22.5%）略收，视觉更紧 |
| 字形占位 | `4.5 → 27.5`（23 单位） | 占画布 **72%**；留白 4.5（14%），四周均等 |
| 笔画宽度 | **5.4**（占字高 17%） | 双竖杠与斜杠统一，不因转角变粗 |
| M 的 V 底点 | y=21.2 | 到字高的 72%，不触底——小尺寸下counter（内白）更大，更易辨认 |
| 填充方式 | **实心 path** | 见下节 |

### 路径

```
M4.5 27.5V4.5h5.4L16 13.6l6.1-9.1h5.4v23h-5.4V12.1L16 21.2l-6.1-9.1v15.4z
```

### 为什么用实心而不是描边

细描边在 16px 缩放时会被抗锯齿"吃掉"一部分，笔画变灰发虚；实心轮廓降采样后仍是干净的色块边缘。
这是小尺寸字标的标准做法（Notion / Linear / Slack 的品牌块同理）。

代价：实心 M 比线条 M 视觉更重。当前侧栏底色是深绿、图标是白色，对比够，没有压迫感。

## 三、尺寸与用法

| 场景 | 尺寸 | 圆角 | 字标渲染 | 文件 |
| --- | --- | --- | --- | --- |
| 浏览器标签 | 32（自动取 favicon.svg） | 7 | 全尺寸 | `public/favicon.svg` |
| 侧栏品牌块 | 30 容器 | 由 `--r-sm` 决定 | 18px 内联 SVG | `index.html` |
| 折叠态侧栏 | 同上 | — | 同上（文字隐藏，图标保留） | 同上 |
| 未来社交分享卡 | 512 / 1024 | 7/32 等比 | 全尺寸 | 用同一 path 放大，不要重画 |

两处都用**同一套几何**，区别只在 `viewBox`：favicon 用 32 网格，侧栏内联用 24 网格（等比 0.75）。

## 四、颜色：现状与建议

### 现状（本次保持）

| 位置 | 颜色 |
| --- | --- |
| 标签页 favicon | `#534AB7`（靛蓝） |
| 侧栏品牌块 | `linear-gradient(135deg, #17B98F, #0E6E5C 60%, #0A5849)`（墨绿） |

### 建议统一成墨绿（推荐）

理由：① 侧栏是用户停留最久的地方，那才是事实上的品牌色；② "Miku" 本身是青绿色联想；③ 靛蓝在界面里主要用作 `tag purple`（标签），当品牌色会与功能色混淆。

改法（一行）：

```html
<!-- public/favicon.svg：把 fill 换成绿色渐变 -->
<defs>
  <linearGradient id="g" x1="0" y1="0" x2="1" y2="1">
    <stop offset="0" stop-color="#17B98F"/>
    <stop offset=".6" stop-color="#0E6E5C"/>
    <stop offset="1" stop-color="#0A5849"/>
  </linearGradient>
</defs>
<rect width="32" height="32" rx="7" fill="url(#g)"/>
```

### 想反过来统一成靛蓝

改 `public/styles.css` 的 `.brand-mark { background: ... }` 为 `#534AB7`，并把 `box-shadow` 的色相一起调。

> 统一之后，浏览器标签和侧栏才是同一个品牌。现在属于"两套视觉资产并存"，交接时容易被问。

## 五、使用禁区

- **不要拉伸**：宽高必须等比，M 变形后斜杠角度就废了
- **不要加描边/投影**：实心字标加描边会在小尺寸下糊成一团
- **最小尺寸 16px**：再小请改用纯色块，不放字标
- **不要给 M 换字重**：它不是字体，是画出来的路径；"加粗"要改笔画宽度并重新算 V 的交点
- **深色底才用白字标**：浅色底请改用靛蓝/墨绿字标，别用白
