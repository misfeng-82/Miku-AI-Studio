# 短剧题材库扩展方案

> 适用项目：`comic-drama-agent`（Miku AI 创作平台）
> 落点代码：`src/assets/genreLibrary.js`（新增）、`src/services/scriptGenService.js`、`src/routes/api.js`、`public/views/script.js`
> 现状：改造前题材只是前端一个 6 项的下拉框（`public/views/script.js` 的 `GENRES` 常量）+ 后端 prompt 里原样回填的一个字符串，题材没有任何创作约束力。

## 一、调研：AI 短剧的主流题材方向与开源分类做法

### 1.1 行业口径：题材是有「枯荣」的，不能只收传统爆款

DataEye 短剧热力榜（经中国网络视听协会《2024 微短剧行业生态洞察报告》引用）给出的 2023→2024 题材结构变化，是这次题材库必须带「热度档位」字段的直接依据：

| 题材 | 2024 数量占比 | 2023 数量占比 | 趋势 |
|---|---|---|---|
| 女频 | 41.0% | 40.7% | 持平，仍是最大盘 |
| 情感 | 39.6% | 37.8% | 稳中有升 |
| 男频 | 23.9% | 51.3% | **腰斩** |
| 都市 | 23.7% | 15.5% | +142.4% 强势增长 |
| 逆袭 | 22.3% | 24.4% | 基本盘 |
| 甜宠 | 9.5% | 15.4% | 退潮 |
| 家庭 | 8.0% | 2.6% | **+409.5%，增速第一** |
| 战神 | 7.3% | 17.3% | **-59.4%** |
| 古装 | 5.7% | 6.9% | 微降 |
| 重生 | 4.9% | 7.2% | 降 |
| 萌宝 | 3.7% | 4.1% | 持平 |
| 神医 | 2.1% | 6.4% | **-77.8%** |
| 赘婿 | 1.4% | 4.9% | **-69.2%** |
| 系统 | 0.6% | 0.9% | **-80%** |
| 悬疑 / 科幻 / 民国 / 末日 | 0.7% / 0.3% / 0.3% / 0.2% | 0.4% / 0.1% / 0% / 0% | 小众但增速为正 |

按热力值口径（谁真的赚钱）：情感 63.3%、女频 61.8%、逆袭 50.5%、都市 43.2%、男频 39.3%、家庭 20.7%、甜宠 18.0%、古装 14.5%。

**结论**：题材库不能只列「当下最火」的，必须同时覆盖三类——`hot`（情感/逆袭/都市/甜宠）、`rising`（家庭/年代/都市异能）、`niche`（悬疑/民国/末世）。传统男频爆款（战神/赘婿/神医/系统）仍要保留，但要在 `pitfalls` 字段里写清「这个题材已经退潮，必须换外壳」，而不是继续骗用户说这是爆款。

### 1.2 平台口径：题材不是一个字符串，是「多值标签 + 维度坐标」

红果短剧的榜单标签是典型样本（AI 短剧榜 TOP20 抓取）：

> `#赘婿逆袭 #王妃 #古代 #男频`、`#女频 #萌宝 #豪门恩怨 #团宠`、`#异能 #种田 #年代 #大男主 #男频`、`#都市日常 #无敌神医 #穿越 #男频`、`#女频 #现代言情 #破镜重圆 #职场 #总裁`、`#系统 #逆袭 #娱乐圈 #男频`

一部剧通常挂 3–6 个标签，且**任何单个标签都不足以定位一部剧**。同时榜单里能观察到结构性的组合规律：2026 年 10 月 AI 短剧榜 TOP20 中，带 `年代/乡村/种田` 的作品占 7 席——这是 AI 出图在当前阶段最划算的赛道（老物件、旧场景、低特效需求）。

**结论**：数据结构必须是「大类（单选）+ 频道 + 时代 + 篇幅 + 多标签 + 爽点优先序」，而不是 `genre: string`。

### 1.3 开源项目的分类做法（4 个项目）

| 项目 | 分类方式 | 值得借鉴的点 | 不采用的点 |
|---|---|---|---|
| [lism/short-drama](https://github.com/lism/short-drama)（MIT） | 13 种题材，**可组合最多 2 个**；另有受众（女频/男频/全龄）、调性（甜/虐/甜虐/爽/燃/搞笑）、结局（HE/BE/OE）、集数、语言、国内/海外模式 | ①「题材可组合」；② 8 类爽感矩阵（打脸/逆袭/甜宠/虐心/悬疑/燃/搞笑/感动）；③ 5 种钩子类型（悬念/反转/情绪/信息/危机）；④ 节奏曲线四段配比 + 付费卡点 10–15% | 13 个题材颗粒度太粗（「都市」「玄幻」这种是背景不是题材），且没有爽点/配比字段 |
| [Dexter753/ai-short-drama-system](https://github.com/Dexter753/ai-short-drama-system)（MIT） | 题材用 **`id` + 描述**（`suspense`/`romance`/`timeTravel`/`urban`/`fantasy`/`comedy`/`historical`/`horror`），并暴露 `GET /api/script/genres` 给前端取列表 | ① id 稳定、后端下发；② 前端不硬编码中文字符串 | 只有 8 个题材，且没有「受众/时代」维度 |
| [A-cat-with-carrots/OnlyShot](https://github.com/A-cat-with-carrots/OnlyShot) | 在题材之上再加一层「流派」：红果纯爽 / 精品悬疑 / 漫剧奇观 / 沙雕轻喜 / 年代爽剧 | 「同题材 + 不同流派」是防串味最低成本的一刀 | 流派与题材耦合在一起，没有拆成独立维度 |
| [zhaihao118/Micro-Drama-Skills](https://github.com/zhaihao118/Micro-Drama-Skills) | 10 种内置视觉风格，每种是一段 `prompt_suffix`，追加到所有生成提示词末尾 | 「题材/风格用 prompt 后缀注入，而不是改模板」的工程做法 | 只做风格不做题材 |

### 1.4 提炼出的分类思路（本方案的 5 条设计原则）

1. **两级结构**：大类（9 个，决定叙事语法）→ 题材（32 个，决定爽点与桥段）。不把「都市」「古装」当题材，它们只是 `era`。
2. **坐标化**：每个题材带 `channel / era / formats / heat` 四个维度，前端可筛选、后端可排序、文档可解释。
3. **爽点可计算**：每个题材给 `thrills`（优先序）+ `beatBias`（每集配比，和为 1），大纲阶段直接当配额用，模型不再自由发挥。
4. **配比可落地**：`castBias`（主角组/反派/配角人数）+ `variants`（差异化组合维度），把「题材」翻译成「人物表」和「开局」。
5. **id 稳定、后端下发**：题材 id 存进项目与前端 state，改名不影响历史数据；前端只渲染 `/api/meta` 下发的表。

## 二、题材清单（32 个：6 原有 + 26 新增）

### 2.0 维度与标记说明

| 维度 | 取值 | 作用 |
|---|---|---|
| 大类 `category` | 都市逆袭 / 豪门婚恋 / 古装权谋 / 年代乡土 / 玄幻仙侠 / 悬疑罪案 / 萌宝亲子 / 民国传奇 / 校园娱乐 | 分组展示 + 决定叙事语法 |
| 频道 `channel` | 女频 `female` / 男频 `male` / 全龄 `all` | 投流口径，影响人物配比与情绪密度 |
| 时代 `era` | 现代 / 年代 / 民国 / 古代 / 仙侠玄幻 / 未来末世 | 决定美术、服化、道具与 AI 出图成本 |
| 篇幅 `formats` | 微短剧（40 集 × 60–90s）/ 标准短剧（60 集）/ 长剧（100 集） | 直接对到集数与单集秒数（引擎门按秒判） |
| 热度 `heat` | `hot` / `rising` / `niche` | 仅用于排序提示与文档说明，不参与硬判定 |
| 状态 | **原有**（6 个，`legacy: true`，id 与中文名保持不变）/ **新增**（26 个） | 兼容老用户的 localStorage 选择 |

## 三、加入方案

### 3.1 数据结构：一个配置文件，字段即提示词素材

**位置**：`src/assets/genreLibrary.js`（与 `storyFrameworks.js`、`stylePresets.js` 同级，同一套「常量表 + `xxxById()` + `xxxBlock()`」范式）。

**为什么用配置文件而不是数据表**：题材是随行业变化的内容资产，改一个爽点优先序不该走数据库迁移；且 32 条数据量小、需要在 prompt 里整段渲染，JS 常量表能直接 `import` 到服务端与构建期校验，零 IO。等真需要让运营在线改题材时，再把这 32 条迁进表即可——字段设计不变。

**字段设计**：

| 字段 | 类型 | 是否必填 | 进不进提示词 | 说明 |
|---|---|---|---|---|
| `id` | string | ✅ | 否 | 稳定标识，存 `project.json` 与前端 state；改名不影响历史数据 |
| `name` | string | ✅ | ✅ | 展示名；原有 6 个保持不变（localStorage 里存过名字） |
| `legacy` | boolean | 否 | 否 | 是否为改造前就有的题材（前端标「新」用） |
| `category` | enum | ✅ | ✅ | 9 个大类之一 |
| `channel` | `female`/`male`/`all` | ✅ | ✅ | 受众频道 |
| `era` | enum | ✅ | ✅ | 时代（决定美术与出图成本） |
| `formats` | string[] | ✅ | 否 | 适配篇幅（前端筛选用） |
| `heat` | `hot`/`rising`/`niche` | 否 | 否 | 热度档位，仅排序提示 |
| `tagline` | string | ✅ | ✅ | 一句话定位 |
| `audience` | string | ✅ | ✅ | 目标受众（谁在看、为什么看） |
| `thrills` | string[] | ✅ | ✅ | 爽点优先序，第一项是主爽点 |
| `tropes` | string[] | ✅ | ✅ | 剧情钩子/母题池（提示词里是「挑 3–5 个」，不是必写清单） |
| `keywords` | string[3–5] | ✅ | ✅ | 标签，对齐红果多值标签体系 |
| `opening` | string | ✅ | ✅ | 示例开篇（标注「只学口吻，剧情必须换」） |
| `castBias` | `{leads,villains,supports}` | 否 | ✅ | 人物配比，直接翻成「主角组 N 位、反派 N 位、配角 N 位」 |
| `beatBias` | `Record<爽点, number>` | 否 | ✅ | 每集爽点配比（和为 1），大纲阶段当配额 |
| `pitfalls` | string | ✅ | ✅ | 这个题材最容易翻车的地方（防串味的负向约束） |
| `variants` | `{key,label,values[]}[]` | 否 | ✅ | 差异化组合维度：每次生成取一组，组合空间决定「同题材不重样」 |

**配套工具函数**（同文件导出）：

| 函数 | 作用 |
|---|---|
| `genreById(id)` | 容错查询：认 id、认旧中文名、未知 id 回落默认题材（前端存了过期 id 不会崩） |
| `genreCatalog()` | `/api/meta` 下发的精简清单（不含 `opening`/`pitfalls` 长文本，省流量） |
| `genreBlock(genre, {variant, avoid})` | 拼「题材坐标」提示词段（含差异化设定与禁止复用清单） |
| `castBiasText(genre)` | 人物配比 → 一句人话 |
| `beatBiasText(genre, episodes)` | 爽点配比 → 「爽点配额 + 每 N 集一个大爆点」 |
| `pickVariant(genre, seed)` / `variantSpace(genre)` | 按 seed 取一组变体 / 算组合空间 |
| `genreFingerprint(genreId, variant, title)` | 题材指纹，用于记账与去重 |

### 3.2 提示词接入：三处注入，各管一段

改造前 `genre` 只是 `STORY_USER` 里的一个回填字段（`"genre": "${genre}"`），模型看到「都市重生复仇」五个字，怎么写全靠自由发挥。现在改成**三段分别注入**：

#### ① story 阶段（`generateStory`）——题材坐标进用户消息

`src/services/scriptGenService.js`：

```js
const STORY_USER = (concept, genre, episodes, extra = {}) => `【用户创意】
${concept}

${extra.block ?? ''}          // ← genreBlock：定位/受众/时代/爽点优先序/桥段池/标签/参考开篇/差异化设定/翻车点/禁止复用

【任务】
基于上面的创意构建一部 ${episodes} 集短剧的故事蓝本。题材必须是「${genre}」，题材坐标里的爽点优先序、桥段池、差异化设定都要落实。
人物配比：${extra.cast || '主角组 2 位、反派 2 位、配角 4 位'}。
...
```

实际渲染出来是这样（以「七零团宠」为例，`variantSeed: 2`）：

```text
【题材坐标】
- 题材：七零团宠（年代乡土）
- 定位：穿成七十年代家里最不受待见的那个，结果全家都开始护着她
- 受众：女频，35–60 岁女性，看的是「清贫日子里的暖」与年代还原
- 时代与美术：年代（七零八零九零，乡村与厂矿）
- 本题材的爽点优先序：感动 > 逆袭 > 甜宠 > 搞笑（第一个必须是全剧的主爽点）
- 可用的剧情桥段池（挑 3–5 个用，不要全塞）：知青下乡、粮票布票、供销社、重男轻女、一家人的饭桌
- 标签：年代 / 七零 / 团宠 / 种田
- 参考开篇（**只学口吻与信息密度，剧情必须换**）：林小满穿过来的时候，正被亲妈按在炕上骂……
- 本次差异化设定（必须用，别绕开）：role：供销社售货员；conflict：重男轻女
- 这个题材最容易翻车的地方：年代细节一错就出戏——先定死粮票、工分、供销社这三样……
```

#### ② outline 阶段（`generateOutline`）——爽点配额进分集大纲

```js
const g = genreById(story?.genreMeta?.id);      // normalizeStory 会抹掉 genreMeta，先取出来
const genreRules = g ? beatBiasText(g, total) : '';
...
user: OUTLINE_USER(s, b, batchEnd, prev, { genreRules })
```

渲染为：

```text
【题材配额】（不是建议，是本题材的排布口径）
爽点配额：感动 约 35%、逆袭 约 25%、甜宠 约 20%、搞笑 约 20%；每 6 集必须有一个「感动」大爆点，第 1 集就给第一个
```

同时把 `OUTLINE_SYSTEM` 第 5 条的爽点词表统一成 9 类矩阵（原来写的是「打脸/揭破/反转/危机/温情」，和题材配比用的不是一套词，对不上账）。

#### ③ episode 阶段（`generateEpisode`）——只留一句「别写成别的题材」

```js
const genreLine = g ? `${g.name}：爽点优先 ${g.thrills.slice(0, 3).join(' > ')}，别写成别的题材的腔调` : '';
```

**为什么这一层只给一句话**：单集正文的「写什么」已经由本集大纲决定，题材再啰嗦就会和大纲抢话，模型容易两头顾不上。题材在这里只负责语气与腔调。

### 3.4 防重复与串味：五道闸

同题材反复生成最容易出两个病：**重复**（剧名、主角名、开局撞车）和**串味**（写着写成本题材的刻板印象，或几个题材混成四不像）。对应五道闸：

| # | 闸 | 机制 | 代码位置 |
|---|---|---|---|
| 1 | **组合空间** | 每个题材带 1–2 个 `variants` 维度（如「重生节点 × 复仇工具」= 5×4=20 组），全库合计 591 种开局 | `genreLibrary.js` 的 `variants` / `variantSpace()` |
| 2 | **变体递增** | 前端每生成一次 `genVariantSeed += 1`，服务端据此取下一组，连点两次不会拿到同一开局 | `runners.genStory` → `pickVariant(g, seed)` |
| 3 | **撞名黑名单** | 服务端从近 6 个项目里收剧名与主角名，拼成 `【禁止复用】` 段进提示词；不靠前端传，换浏览器/清缓存也生效 | `api.js` 的 `recentAvoid()` + `genreBlock(_, {avoid})` |
| 4 | **撞名重试** | 生成后本地比对：剧名完全相同，或主角名与历史某部重合 ≥2 个 → 换一组变体重写一稿；两稿都撞则报错，**绝不悄悄返回同题剧本** | `scriptGenService.titleClash()` + `generateStory` 的 2 轮循环 |
| 5 | **负向约束** | `pitfalls` 字段进提示词（「这个题材最容易翻车的地方」）；`opening` 标注「只学口吻与信息密度，剧情必须换」；多选题材的辅助题材写成「只借桥段气质，不要改主线」 | `genreBlock()` 的渲染 + `runners.genStory` 的融合参考文案 |

补充一条工程口径：`story.genreMeta.fingerprint`（形如 `retro-70s-pet#conflict=重男轻女|role=供销社售货员@剧名`）会跟着 story 走，后续要接「同题材去重」或「爆款复盘」时，这条指纹就是现成的分组键。

#### 示例 C：宫斗权谋（`palace-scheme`）

| 层级 | 实际注入内容 |
|---|---|
| **题材坐标** | 时代＝古代；频道＝女频；爽点＝反转 > 悬疑 > 虐心 > 打脸；桥段池＝选秀入宫、位分晋升、药里下毒、朝堂与后宫联动、皇子之争；**翻车点**＝最怕「靠皇帝宠爱解决一切」，胜负手必须落在制度与人证上 |
| **差异化设定** | `stake：家族平反`；`identity：太医院女官` |
| **人物配比** | 主角组 2 位、反派 4 位、配角 4 位（宫斗的反派是分层的：小反派/中反派/大反派/隐藏反派） |
| **分集配额** | 反转 35%、悬疑 25%、虐心 25%、打脸 15%；每 8 集一个「反转」大爆点 |
| **落成大纲** | 第 1 集：药方被换、她被推出来顶罪（悬疑+反转，major）→ 第 8 集：翻出太医院旧档、证明父亲冤案（反转，major）→ 第 16 集：朝堂对质（反转+打脸，major） |

#### 三条映射的通用规则

1. **爽点优先序的第一项 = 全剧主爽点**，也是 `beatBias` 里占比最高的那一项（一致性由自测校验：`thrills[0]` 必须出现在 `beatBias` 里，且是最大值时可人工复核）。
2. **人物配比跟题材走，不跟集数走**：宫斗 10 个角色是常态，甜宠 6–7 个就够；`castBias` 之和即目标人数。
3. **大爆点间隔按篇幅算**：微短剧（40 集）每 6 集一个，长剧（100 集）每 8 集一个——`beatBiasText()` 里已按 `episodes` 自动切换。
