# 「去 AI 味」：从绘梦移植的说明

> 对应工具：侧栏「质量把控 → 去 AI 味」
> 相关文件：`src/engine/deaiScan.mjs`、`src/assets/deaiRules.js`、`src/services/deaiService.js`、`public/views/deai.js`

## 一、原项目里「生成 / 管理小说内容」的核心是什么

绘梦（`绘梦/core + skills + pipelines`）不是一个大函数，而是四层可替换结构：

| 层 | 位置 | 职责 | 输入 → 输出 |
| --- | --- | --- | --- |
| 技能包 | `skills/<family>/<skill>/{skill.json,prompt.md}` | 一个能力 = 一份元数据 + 一段提示词。`context` 声明要哪些上下文块，`slots` 声明要哪些参数 | 参数 + 上下文 → 模型输出 |
| 上下文装配 | `core/context.js` | 按技能声明的 `context` 拉取设定/大纲/人物/上一章/反 AI 规则，按预算裁切后拼进 user 消息 | 项目 id + 参数 → messages |
| 流水线 | `pipelines/*.json` + `core/pipeline.js` | 把「技能步骤 + 本地步骤（量化扫描 / 落盘）」串成一条带门禁的链；`{{last}}`、`{{as:xxx}}` 在步骤间传值 | 流水线 id + 参数 → 章节文件 |
| 量化扫描 | `tools/deai_scan.py` | 13 维实测 AI 痕迹分（0–100），给门禁用 | 文本 → 报告 JSON |

一条典型链路（`write-chapter.json`）：
`L0 锚定 → 生成正文 → L1 量化扫描（门禁 ≤55）→ 红队审查 → 去 AI 味改写 → 复扫定档（门禁 ≤40）→ 写入章节文件`

**可移植性评估**：技能包与流水线是「数据驱动 + 纯文本提示词」，最容易被别的产品复用；扫描器是纯标准库 Python，逻辑干净，但引入 Python 运行时会打破本项目「零依赖 Node」的前提；项目管理（`core/store.js` 的 markdown 目录树）与 Electron 外壳绑定的是「桌面软件」形态，和本项目的「单页工作台 + JSON 数据」是两套模型。

## 二、本项目实际移植了什么、为什么

**移植了**（保留了原版最硬的那块能力）：

1. **13 维量化扫描器** → `src/engine/deaiScan.mjs`，Python 逐条重写为纯 JS。
   词表 12 组、13 个维度权重、惩罚曲线、样本量保护、「加权均值 0.62 + 最差单项 0.38」的短板放大公式，全部保持一致。
   已用同一段文本做过原版对照：**原版 13.4 / 移植版 13.4，每个维度的惩罚值逐项相同**。
2. **反 AI 规则库** → `src/assets/deaiRules.js`：10 条本机规则 + 六项诊断 + 减法 7 项 + 加法 5 项。规则单独成文件，是因为提示词、界面展示、扣分解释三处都要用它。
3. **门禁式改写闭环** → `src/services/deaiService.js`：扫描 → 带实测诊断改写 → 复扫 → 不过门带「上一轮没过的维度」再改一轮。对应原版 `write-chapter` 里的 G1 与定稿门禁。
4. **输出解析** → `splitRewriteOutput()`：认「### 一、修改后全文 / ### 二、修改记录 / ### 三、未处理项」三段，抽不到就退化为「修改记录之前的部分当正文」，避免把表格写进正文。

**没有移植**（并说明原因）：

| 未移植 | 原因 |
| --- | --- |
| 50 个技能包 + 技能加载器 | 那是「换提示词不用改代码」的产品形态；本项目每个工具是代码 + 固定提示词，硬塞进来会变成两套并存的心智模型 |
| 项目 / 章节的 markdown 目录树（`store.js`） | 本项目的数据形态是 JSON 仓库 + 作品库（只读），再引一套 Markdown 文件树会让「作品」有两个家 |
| Electron 桌面壳、Python 运行时 | 与本项目「单文件 Node 服务 + 浏览器」的交付形态冲突，且会破坏零依赖 |
| 七阶段续写引擎（`continue_engine.js`） | 它依赖「整本书的项目状态 + 章节台账」，属于「写长篇」的产品闭环，不是单个工具能承载的；本项目已有增量式剧本生成，重复度低 |

## 三、与原版的差异（适配本项目的部分）

1. **对话识别**：原版只认中文引号（“…”/「…」）。短剧剧本是「角色：台词」的行格式，只按引号算会把整集对话占比判成 0、直接顶满惩罚。移植版两种都认，并排除「注：」「旁白：」这类元信息行与场号行。
2. **正文抽取**：原版按「## 正文」小节抽取（小说章节格式）。剧本没有这套小节，抽不到就整篇扫，不硬套小说模板。
3. **门禁形态**：移植版额外输出 `deaiGate()`，结构与项目其他引擎的 `{id,label,ok,detail}` 一致，可以和 24 道质量门并列展示。
4. **短样本保护**：正文 < 300 字时门禁标记 `soft:true`（只报分不判死），与原版「不足以判定」的提示一致，但改成了结构化字段而不是靠界面看文案。
5. **未接模型时的行为**：扫描照常可用（纯本地）；改写如实返回 `skipped:true` 并说明原因，不返回假正文——与原版演示模式的「占位文本」故意不同，避免用户以为改过了。

## 四、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/deai/scan` | `{ text, maxScore? }` → `{ report, gates, maxScore }`，纯本地，不花额度 |
| POST | `/api/deai/rewrite` | `{ text, target?, rounds? }` → `{ before, after, text, record, pending, rounds, gates, note }`，调模型 |
| GET | `/api/deai/rules` | 规则库快照（10 条规则 + 六项诊断 + 减法/加法清单） |

## 五、怎么验证它真的对

```bash
node scripts/selftest.mjs     # 9 项扫描器单测：确定性、词表非空、短样本不当真、剧本对话识别、正文抽取
node scripts/featuretest.mjs  # 8 项接口测试：正常/确定性/空文本 422/缺字段 422/规则库/未接模型跳过
node scripts/rendercheck.mjs  # 视图三态渲染：空态 / 扫描后 / 改写结果
```

## 六、授权提醒（重要）

原项目 `绘梦/package.json` 里写的是 `"license": "UNLICENSED"`（保留所有权利）。本移植属于**算法与词表的再实现**，不是复制原文件，但词表、权重与规则文案来自原项目。

- 如果绘梦是你自己写的：把它的许可改成 MIT/Apache-2.0，并在 `NOTICE` 里记一笔来源，就可以公开。
- 如果绘梦是别人的 / 来源不明：公开仓库前建议二选一——① 取得作者授权；② 把词表与规则文案换成自己整理的一套（结构与权重可以保留，那是通用方法），再声明为原创实现。

代码里已经在文件头标注了移植来源，便于日后追溯。
