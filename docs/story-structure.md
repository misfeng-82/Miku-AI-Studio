# 短剧结构资产方案（付费卡点 · 四层反派 · 钩子排布 · 节奏曲线）

> 落点代码：`src/assets/storyStructure.js`（新增）
> 接入：`src/services/scriptGenService.js`、`src/routes/api.js`、`public/views/script.js`
> 与题材（`src/assets/genreLibrary.js`）、框架（`src/assets/storyFrameworks.js`）是三个正交维度：题材管「用什么词」，框架管「走什么套路」，结构管「集数怎么排、钱在哪收」。

---

## 一、调研：为什么要补这一层

上一轮补了题材库（32 个题材的坐标化），但同一题材的两部剧，观众付费与否**不取决于题材，取决于结构**：卡在第几集、反派分几层、每集结尾留什么扣。这几件事在开源体系里是**有确定答案的**，不是创作自由。

### 1.1 来源与核心事实

全部来自 [lism/short-drama](https://github.com/lism/short-drama)（MIT）的 4 份参考文档，本轮按原文口径落地：

| 文档 | 行数 | 拿到的事实 |
|---|---|---|
| `paywall-design.md` | 220 | 卡点黄金位置（首卡 8–12 集、二卡 18–25 集、三卡 35–45 集、终极卡倒数 3–5 集）；密度按总集数分档；间隔 ≥5 集；前 10 集最多 2 个；5 种卡点套路；5 条禁忌 |
| `villain-design.md` | 319 | 四层反派（小/中/大/隐藏）的活跃区间、三段式交锋、伏笔 ≥3 处、退场方式、反派三问 |
| `hook-design.md` | 310 | 5 种钩子的分阶段配置、题材侧重表、叠加规则、「连续 3 集不用同类钩子」自检 |
| `rhythm-curve.md` | 263 | 四段式：起势 15% → 攀升 30% → 风暴 35% → 决战 20% |

### 1.2 关键设计决定

**这些东西全部做成确定性函数，不交给模型。** 理由：卡点落在第几集、反派第几集退场，是**排版问题**不是创作问题——模型每次发挥都会给出不同的答案，而下游（投流、资产生成）需要的是稳定的结构。模型负责写剧情，代码负责排骨架。

## 二、四条规则与落地

### 2.1 节奏曲线：四段式

| 段落 | 占比（40 集） | 任务 | 可用钩子 | 强度 |
|---|---|---|---|---|
| 起势段 | 15%（1–6 集） | 建立角色与核心冲突，累积 ≥3 个未解悬念，展示一次小规模爽点 | 悬念钩、信息钩 | 中等 |
| 攀升段 | 30%（7–18 集） | 中反派登场并至少赢主角一次，情绪投入加深，**卡点密度最高** | 悬念钩、情绪钩、反转钩 | 中等偏强 |
| 风暴段 | 35%（19–32 集） | 大反派显露真身，高密度刺激，主角先受挫再翻盘 | 反转钩、危机钩、信息钩 | 强 |
| 决战段 | 20%（33–40 集） | 终极对决（2–3 集），可选揭露隐藏反派，**最后一集不设钩子、给圆满收束** | 危机钩、反转钩、悬念钩 | 最强 |

代码：`RHYTHM_STAGES` / `rhythmPlan(total)` / `rhythmStageOf(ep, total)`。

### 2.2 付费卡点

**规划规则**（`paywallPlan`）：

| 规则 | 取值 | 来源 |
|---|---|---|
| 卡点占比 | 按总集数取 ~12%（落在原文的 10–15%） | 原文「10-15% 的集数设为付费卡点」 |
| 首个卡点 | 第 8–12 集（短剧按比例提前，但至少留 2 集免费） | 原文「黄金卡点位置」 |
| 卡点间隔 | ≥5 集 | 原文「卡点间隔：最少间隔 5 集」 |
| 终极卡点 | 倒数 3–5 集 | 原文「倒数3-5集」 |
| 集数太短 | <8 集不设卡点 | 本项目补充（没有付费墙的意义） |

**实测结果**（`paywallPlan` 输出）：

| 总集数 | 卡点数 | 占比 | 卡点位置（套路） |
|---|---|---|---|
| 10 | 1 | 10% | 7（身份即将揭露） |
| 40 | 5 | 12.5% | 10 身份 / 17 真相 / 24 情感 / 31 阴谋 / 38 危机 |
| 60 | 7 | 11.7% | 10 / 18 / 26 / 34 / 42 / 50 / 58 |
| 100 | 12 | 12% | 10 / 18 / 26 / … / 98 |

**5 种卡点套路**（`PAYWALL_PATTERNS`，按索引轮转，保证相邻卡点不同套路）：

| 套路 | 做法 | 适配 |
|---|---|---|
| 身份即将揭露 | 铺垫够了「被看不起」，在真相揭露的前一秒切断 | 现代 / 古代 / 民国 |
| 生死一线 | 主角陷入绝境，在是死是活揭晓前切断 | 古代 / 仙侠 / 末世 |
| 情感爆发中断 | **断在「差一点就甜到」的位置**，不是甜够了再断 | 现代 / 民国 |
| 反派阴谋得逞 | 主角跌到谷底、反派举杯庆祝的瞬间切断 | 现代 / 年代 / 古代 |
| 真相即将大白 | 核心谜题的证据出现，在辨认出「是谁」的前一刻切断 | 现代 / 古代 / 仙侠 |

**5 条禁忌**（`PAYWALL_DONT`，进 prompt 当禁令）：无悬念硬切、虚假悬念（下集 10 秒化解）、关键信息提前泄露、连续多集卡同一悬念、卡在无关紧要的小事上。

### 2.3 四层反派

| 层级 | 活跃区间 | 数量 | 硬要求 | 退场 |
|---|---|---|---|---|
| 小反派·炮灰级 | 前 15% | 1–2 | 嚣张但无实力支撑；惨状写足；退场干脆 | 一次打脸认怂 / 被靠山抛弃 / 自食其果 |
| 中反派·主要对手 | 15%–45% | 1–2 | **三段式交锋**：小胜 → 受挫（低谷）→ 翻盘；至少要赢主角一次 | 被更高实力击败 / 被当弃子 / 阴谋败露 |
| 大反派·终极 Boss | 45%–80% | 1 | 出场有仪式感（先只闻其名）；有人性的一面；结局让观众觉得「该！」 | 正面碾压 / 众叛亲离 / 伏法 |
| 隐藏反派·终极反转 | 80%–100% | 0–1（**可选**） | 至少 3 处可回溯伏笔；伏笔不能太明显；没埋够就不要设 | 情感维度的最终对决 |

**反派三问**（每个反派必须回答）：为什么做坏事（动机）／能力从哪来（支撑）／为什么不更早动手（节制）。

**题材适配**：甜宠、萌宝、末世这类「不靠对抗驱动」的题材只排 3 层（`villainPlan` 按 `category` 自动过滤隐藏反派）——原文明确「甜宠和末日重生等题材不一定需要完整的四层反派」。

代码：`VILLAIN_TIERS` / `villainPlan(total, genre)` / `villainText()` / `VILLAIN_QUESTIONS`。

### 2.4 集尾钩子

**分阶段配置**（见 2.1 表）+ **题材侧重**（`HOOK_BIAS`）：

| 大类 | 主钩子 | 副钩子 | 慎用 |
|---|---|---|---|
| 都市逆袭 | 悬念、危机 | 信息 | 情绪 |
| 豪门婚恋 | 情绪 | 悬念 | 危机（破坏甜感） |
| 古装权谋 | 反转、危机 | 悬念 | — |
| 年代乡土 | 情绪、危机 | 信息 | — |
| 玄幻仙侠 | 危机 | 悬念 | 情绪 |
| 悬疑罪案 | 信息、悬念 | 反转 | 情绪 |
| 萌宝亲子 | 情绪 | 悬念 | — |
| 民国传奇 | 情绪、反转 | 危机 | — |
| 校园娱乐 | 情绪、悬念 | 反转 | — |

**排布算法**（`hookPlan`）：从本段落候选池挑 → 按题材侧重排序 → **连续 3 集不得重复** → 卡点集用本段最强钩子 → 最后一集不设钩子。

## 三、接入链路

### 3.1 三段 prompt 各加一段

| 阶段 | 注入内容 | 代码 |
|---|---|---|
| story | 反派分层表（层级/活跃集数/硬要求）+ 反派三问；人物表 JSON 增加 `villain` 字段 | `villainText()` 进 `STORY_USER` 的 `extra.villain` |
| outline | 全剧结构块（节奏四段 + 卡点表 + 钩子分段落配置）+ **本批每集的钩子类型已经排定，模型照抄** | `structureBlock()` 与 `hookAssign` 进 `OUTLINE_USER` |
| episode | 本集结构定位（第几段 / 集尾用什么钩子 / 是不是卡点，卡点给具体套路） | `episodeStructure()` 进 `EPISODE_USER` |

### 3.2 结构落进契约

大纲契约的每一集现在带三个字段（`assembleOutline` 确定性回填，模型填的只作参考）：

```json
{ "ep": 10, "hookType": "信息钩", "paywall": true, "stage": "rise", ... }
```

人物表的反派带层级（`normalizeStory` 兜底：模型漏标时，按「定位写反派的角色」顺序补 `small → mid → boss → hidden`）：

```json
{ "name": "顾景琛", "role": "反派/前未婚夫", "villain": "boss", "desc": "…" }
```

| 文件 | 改动 |

### 3.4 参数映射示例（都市重生复仇，40 集）

| 层级 | 代码排定 | 模型负责 |
|---|---|---|
| 节奏 | 起势 1–6 / 攀升 7–18 / 风暴 19–32 / 决战 33–40 | 每段完成对应任务（如攀升段让中反派赢一次） |
| 卡点 | 第 10 集（身份揭露）／17（真相）／24（情感）／31（阴谋）／38（危机） | 卡在情绪最高点，下一卡点换新悬念 |
| 反派 | 小反派 1–6（1–2 位）／中反派 7–18（1–2 位）／大反派 19–32（1 位）／隐藏反派 33–40（可选 1 位） | 谁是谁、动机三问、怎么被解决 |
| 钩子 | 起势段用悬念/信息，攀升段加情绪与反转，风暴段用反转/危机，决战段用危机/反转；连续 3 集不重样 | 每集结尾 20 字内的卡点内容 |

## 四、验证

| 验证项 | 结果 |
|---|---|
| `node scripts/selftest.mjs` | **79 项全过**（新增 5 条结构库 + 大纲契约校验） |
| 卡点规则 | 40/60/100 集占比 12.5%/11.7%/12%，首卡在第 10 集，间隔 ≥5，终极卡在倒数第 3 集 |
| 钩子规则 | 3 个题材各 40 集，均无「连续 3 集同类钩子」，末集不设钩子 |
| 反派分层 | 对抗题材四层齐全且递进；甜宠自动降为 3 层 |
| 前端渲染 | 反派分层卡、💰 卡点标记、钩子类型标签、段落名 均正常显示 |

## 五、待办

- 卡点集目前只提示模型「停在高潮」，没有**校验**：可以在 `generateEpisode` 后加一道门——卡点集的【钩子字幕】必须落在最后 3 行，且不能是陈述句。需要真模型样本才能定判定阈值。
- `villainCast()` 已导出但未接前端（当前前端直接读 `story.characters[].villain` 自己分组）——等需要「跨集统计反派出场」时再换成它。
