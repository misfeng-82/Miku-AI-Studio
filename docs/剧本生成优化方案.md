## 二、诊断：我们的剧本生成缺什么

我们现在**管住了「形状」，没管「内容」**：

```
已有（结构门 14 + 10 道）          缺（内容维度）
─────────────────────────────    ──────────────────────────
id 合法性、引用覆盖对账              这一集是"压弹簧"还是"放弹簧"
时长 ±15%、台词 ≤22 字              集与集之间如何承接（会不会硬切）
钩子落点钉在第一场第一拍              集内情节点密度（会不会赶戏）
场景/道具/角色不空转                 台词有没有情绪与姿态（水词）
结构完整性                          有没有网文腔（一票否决项）
```

对照那套 v8.8.0 方法体系，我们缺的是这几条**决定"好不好看"的东西**：

| # | 工业级做法 | 我们的现状 | 影响 |
|---|---|---|---|
| 1 | 每集必须声明**压 / 放**弹簧类型，**不允许中间状态** | 无 | 集与集情绪平推，没有起伏 |
| 2 | **loop 骨架**：大 loop（2-8 集故事弧：起承转合）+ 小 loop（攻防回合，跨 2-3 集） | 只有单集拍数，按平均分配 | 每集各自为战，没有跨集蓄力与爆发 |
| 3 | **逐级加码**：每轮冲突必须有一项升级（身份/赌注/危机） | 无 | 三集之后观众就腻 |
| 4 | **呼吸感**：大 loop 收尾后安排缓冲集，禁大高潮接大高潮 | 无 | 全程高压，看着累 |
| 5 | **跨集衔接铁律**：每集开头必须承接上集（时间锚定/场景延续/角色状态） | 无 | 集间像硬切，像单元剧 |
| 6 | **beat 密度 ≤2 个/集**，强情绪爆点要"写满"（≥6-8 句：层层反应+对手戏+微动作） | 只规定场数与拍数（平均分配） | 强冲突被压成电报体，观众觉得"赶" |
| 7 | **台词必带情绪 + 关系姿态**（反水词三判据） | 只有字数上限 | 台词没有咬合力 |
| 8 | **网文腔四病征一票否决**（短句留白/通感比喻/设问句/省略号气口） | 无 | AI 味重，不像剧本像小说 |
| 9 | **首集特殊处理**：独立引流集，5 模块当集闭环 | 无 | 第一集不抓人 |

**一句话结论**：我们缺的不是"让模型写得更长"，而是**给模型一套短剧的节奏纪律 + 一套内容自检**。模型现在只能按"每集 N 场 M 拍"平均铺，所以出来的是"结构正确但不好看"的剧本。

## 三、改进方案（三期，每期一块，可独立验证）

### 第一期：给每一集装上「节奏定位」（成本最低、收益最直接）

**改动**

1. `src/assets/storyFrameworks.js`：每个框架增加 `springPlan` 字段——该框架下各集的弹簧序列模板
   ```js
   // 例：复仇逆袭流
   springPlan: ['press', 'press', 'release', 'press', 'release', 'both', 'release'],
   ```
2. `src/services/scriptService.js` 的 `buildOutlinePrompt`：新增第 8 条硬约束
   ```
   8. 每集必须声明 spring 字段，取值只能三选一：
      press（只压不解决）/ release（只释放）/ both（前半压后半放）
      相邻两集不得连续出现 3 个 press；全剧 release 占比 ≥ 30%。
   ```
3. `buildScriptPrompt`（生成剧本时）：把本集的 spring 明确写进指令
   ```
   本集节奏定位：press（压弹簧）
   - 本集只制造困境/误会/压制，不许在集内给出反转或解决
   - 结尾必须停在"危机升级"的钩子上
   反模式禁令（命中即重写）：
   - 禁网文腔：不写"短句留白堆叠/通感比喻/设问句/省略号气口"
   - 禁水词：每句台词必须读得出谁高谁低、谁在压谁在忍
   - 环境描写每集 ≤2 句、每句 ≤15 字
   - 本集情节点 ≤2 个：最强的那个爆点必须写满（层层反应+对手戏+微动作）
   - 本集开头必须承接上一集结尾（时间锚定句 / 场景延续 / 角色状态承接 三选一）
   ```

**新增校验（做成"内容体检"，只报告不拦截，不动现有质量门）**

| 体检项 | 判据 |
|---|---|
| `spring-declared` | 每集都声明了 spring；没有连续 3 个 press |
| `beat-density` | 每集情节点 ≤2（按场次与台词密度粗估） |
| `no-webnovel-tone` | 扫描四病征：省略号气口、设问句、通感比喻（"仿佛/像……在哭泣"）、单句成段留白 |
| `no-filler-line` | 台词去停用词后长度 <6 字且无情绪词/称呼/动作提示 → 疑似水词 |
| `carry-over` | 每集第 2 集起，第一场的地点或人物与上一集最后一场有交集 |

**验收**：同一创意生成两次剧本 → 体检报告里 5 项全绿；人工读第一集，能明显感到"集集有主张"。

---

### 第二期：loop 骨架（跨集蓄力与爆发）

**改动**

1. 大纲 prompt 增加 `units` 数组（情节单元 = 大 loop）：
   ```json
   {"units":[
     {"id":"U1","fromEp":1,"toEp":3,"start":"反派当众夺走主角的凭证",
      "escalate":["主角自证清白被毁证","反派买通证人"],"turn":"主角亮出备份，反派当场失势"}
   ]}
   ```
   约束：单元覆盖全部集数不重叠；每单元 2-8 集；一部剧 2-5 个单元（按我们的集数体量调低）。
2. 剧本 prompt：把"本集属于哪个单元的哪一段（起/承/转/合）"写进指令，**起/承集禁止提前给出反转**。
3. 新增体检项：
   - `loop-coverage`：单元无缝覆盖全部集数
   - `loop-escalate`：每个单元的 escalate 至少 2 条，且措辞上体现强度递增（对比相邻条目关键词）
   - `breathing`：每个单元收尾后安排 1 个低强度集（我们有 spring 的话：unit 结束后一集是 both 或轻 press）
   - `first-episode`：第 1 集豁免跨集约束，但必须当集闭环（钩子→立人→引爆→留悬念）

**为什么分两期做**：`units` 改的是大纲的数据形状，会牵动现有 `repairOutline` 与 14 道结构门，必须先让第一期跑稳、观察一轮再动。

---

### 第三期：内容体检独立成页（把反模式沉淀成产品能力）

把 v8.8.0 的 17 条反模式**取其中在我们体量下能确定性判定的 8 条**，做成独立页面「剧本体检」：

| 取自 | 判据（可确定性实现） |
|---|---|
| #13 单集闭环（第2集起） | 集内是否有"事件触发→升级→反转→收尾"闭环 |
| #15 网文腔 | 上文四病征正则 + 句长分布 |
| #17 水词 | 台词三判据（删掉是否影响关系 / 换成谁都成立 / 只传信息不传态度）弱化为启发式打分 |
| #1 剧情循环重复 | 相邻单元冲突结构相似度（关键词/动词集合的 Jaccard） |
| #3 表达单调 | 同一动作/表情描写全剧出现 ≥3 次 |
| #14 环境废戏 | 环境描写句数与句长超预算 |
| #9 单循环同质化 | 连续 3 轮解路径同类（按动词分类） |
| #16 电视剧化（子集） | 集内出现分幕词、设定条数 >3、stakes 升级到"世界/王朝存亡" |

输出形态：每条给「命中段落原文 + 为什么命中 + 改写方向」，不给分数（分数留给现有质量门）。

## 四、明确不做的事

- ❌ 不引入任何依赖（不需要 LangChain/LangGraph，这套规则全是提示词 + 纯函数校验）
- ❌ 不改现有 24 道结构门的判定逻辑（内容体检是**并列的新功能**，不是替换）
- ❌ 不改架构（不新增服务层、不改数据流）
- ❌ 不接第二个模型、不做 embedding/RAG（先看看纯规则能走多远）

---

## 五、建议的执行顺序

```
第一期（节奏定位 + 内容禁令）    ← 改动小、见效快、不动数据形状
   ↓ 跑通、你看过效果后
第三期（内容体检页）             ← 把"好不好的判据"变成可见报告
   ↓ 有了报告，第二期的 loop 骨架才好验证
第二期（loop 骨架）              ← 动大纲形状，风险最高，放最后
```

**与既有约束的关系**：三期都在「模型管创意、代码管契约」这条线上——第一期给模型加**节奏纪律**，第二期给模型加**跨集骨架**，第三期给用户加**内容判据**。改动前每次都会先 git commit，一次只做一期。

## 七、可验证的预期效果

| 现在 | 改后 |
|---|---|
| 每集结构一样，都是"铺垫→冲突→结束" | 每集有明确主张：压集只压、放集释放，节奏曲线起伏 |
| 集与集之间跳跃 | 集集首尾相接 |
| 冲突一路平推 | 每轮冲突至少一项升级（身份/赌注/危机） |
| 台词只传递信息 | 台词带情绪与权力姿态 |
| "AI 味"重（像小说） | 只写能拍的东西 |
